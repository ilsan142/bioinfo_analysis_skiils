# 작성자가 입력 점검 후 작성한 설계 예시

2026-10-19. 모두 **합성 자료**이며, [실제 입력 점검 결과](feasibility_checks.json)를 읽은 뒤 작성했다. 새 에이전트가 스킬만 받아 독립적으로 만든 계획이 아니다. 효과 추정·검정은 실행하지 않았다. 각 사례의 실제 입력은 [cases.json](cases.json)에 있으며, 별도 디렉터리에 준비하면 아래 상대 경로를 사용할 수 있다.

## 01 — 같은 donor에서 나눈 두 조건

**질문:** 동일 donor에서 나눈 배양 표본의 treated−control marker 발현 차이를 어떤 설계로 추정할 것인가? 가상 marker panel이며 실제 생물학적 기전을 주장하지 않는다.

**확인한 사실:** `measurements.tsv`는 3개 feature×8개 관측이다. 전체 sample ID 8개가 `metadata.tsv`와 일대일 연결되고 중복·미연결은 0이다. 행렬의 열 순서는 메타데이터와 다르므로 ID로 연결한다. metadata에는 독립 donor 4명과 완전한 pair 4개가 있다. 배치 A와 B에는 각 조건이 2개씩 있으며, 동일 donor의 두 조건은 같은 배치에 속한다. `context.md`에 값이 이미 정규화된 log2 intensity라고 명시돼 있다. 이 의미는 숫자의 모양으로 추정하지 않았다.

**권장 설계:** donor 내 treated−control 차이를 기본 비교로 삼는다. 세포·파일·marker 수를 독립 n으로 세지 않는다. 추가 로그 변환이나 count 전용 모형은 계획하지 않는다. 배치는 donor 안에서 일정하므로 donor 효과와 함께 중복된 배치 항을 자동으로 추가하지 않는다. 모델 구현 시 선택한 항이 실제 설계와 맞는지 다시 확인한다.

| 다음 질문 | 제안한 확인과 이유 | 판단 기준 |
| --- | --- | --- |
| 값의 누락·범위·쌍별 분포가 비교를 뒷받침하는가? | `measurements.tsv`를 ID로 연결해 값의 범위와 누락을 확인하고 donor별 paired plot을 본다. 낮은 n에서 한 관측의 영향을 이해하기 위해서다. | 오류·누락이 있으면 원기록으로 원인을 확인한다. 차이가 크다는 사실만으로 제외하지 않는다. |
| 어떤 효과와 불확실성을 보고할 것인가? | 각 marker의 donor 내 차이, 단위, 독립 n과 분포를 보고한다. 독립 donor 차이의 분포 가정을 확인한 뒤 평균 차이의 구간 등 적절한 방법을 선택한다. | 4명이라는 작은 n의 한계를 남긴다. 검정이 목적에 필요하면 3개 marker 비교 전체를 보정 family로 두고 방법을 명시한다. 정확한 구간 폭이나 유의성을 미리 예측하지 않는다. |
| 특정 donor가 요약을 좌우하는가? | 앞선 결과가 소수 관측에 의존할 때 donor 한 명씩 제외한 기술 요약을 민감도로 비교한다. | 사후 민감도임을 남기며 유리한 제외 결과로 기본 분석을 교체하지 않는다. |

**첫 실행 단계:** 누락·값 범위·donor별 분포 점검이다. ID 연결 검사는 이미 완료했으므로 입력이 바뀌지 않았다면 다시 시작하지 않는다. 설계만 요청받았으므로 해당 단계의 실행은 아직 하지 않았다.

**인계:** 원본 보존, 4개 pair, 비교 방향과 log2 intensity 단위를 유지한다. 완료 시 marker별 관측·효과·가능한 불확실성, 선택 근거, 작은 n의 한계와 재실행 코드를 남긴다. 아직 실제 값 분포와 모델 가정은 검토되지 않았다.

## 02 — 처리 조건과 배치가 완전히 겹침

**질문:** 배치를 고려한 treated−control 고유 효과를 현재 자료에서 구분할 수 있는가?

**실행한 확인:** `measurements.tsv`의 2개 feature×6개 관측은 메타데이터의 6개 sample ID와 중복·누락 없이 연결된다. 독립 donor는 6명이다. 조건×배치 표는 control/A=3, control/B=0, treated/A=0, treated/B=3이다. 처리와 배치는 자료에서 분리되지 않는다.

**설계 결정:** batch 보정을 수행하면 처리 효과를 얻는다는 계획을 세우지 않는다. 현재 자료로 가능한 것은 조건과 배치가 결합된 관측 차이의 기술 요약이다. 이를 처리 고유 효과의 검정으로 제시하지 않는다.

**첫 미완료 단계:** 추가 실험 기록·사용 가능한 표본 목록에서 같은 배치에 두 조건이 포함된 독립 관측이 있는지 확인한다. 추가 관측이 있으면 생물학적 비교 가능성, donor 관계와 설계의 식별 가능성을 다시 점검한다. 없다면 현재 자료의 개별 관측·분포를 기술하고, 조건을 여러 독립 배치에 교차 배치할 필요를 설계 문서에 남긴다.

**미해결 질문과 영향:** 교차 관측이 존재하는지가 추론의 범위를 바꾼다. 다른 보정 알고리즘 선택은 이 정보의 대안이 아니다. 사용자에게 묻는다면 현재 조건×배치 표를 먼저 제시하고 추가 자료의 존재 여부만 구체적으로 확인한다.

**인계:** 별도 처리 효과 추정은 보류 상태다. 설계 검토의 완료와 통계 분석의 완료를 구분한다. 효과량이나 p-value는 계산하지 않았다.

## 03 — 측정값의 의미와 donor 관계가 미제공

**실행한 확인:** `expression.tsv`는 3개 feature×4개 열이며 4개 sample ID가 `metadata.tsv`와 중복·누락 없이 연결된다. 메타데이터는 조건만 제공한다. donor와 배치 정보는 없고, 사용자는 단위와 생성 도구도 전달받지 못했다고 명시했다.

**가능한 설계:** 원값을 보존한 구조·결측·분포 점검은 계속할 수 있다. 소수가 있다는 이유로 TPM이라고 정하거나 반올림하지 않는다. 독립 n, paired/independent 구조, 정규화와 통계 모형 선택은 보류한다.

**다음 정보:** 생성 도구·출력 field, 관측/추정 count인지 정규화·로그값인지, 이전 처리와 donor 관계를 원 제공자 기록에서 확인해야 한다. 이미 모른다고 한 내용을 사용자에게 반복 질문하지 않고 필요한 기록과 그 용도를 한 번 정리한다.

**분기:** count 입력과 독립 반복이 확인되면 그 의미와 설계에 맞는 count 분석을 검토한다. 정규화된 log 값이면 추가 정규화·로그가 필요한지부터 판단한다. 정보가 확보되지 않으면 제한된 기술 요약과 분석 불가 범위를 남긴다. 결과가 아직 없는 상태에서 어느 방법이 유의할지 예측하지 않는다.
