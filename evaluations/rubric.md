# 평가자용 기준

이 파일과 실행 기록은 분석 에이전트에 제공하지 않는다. 입력은 [cases.json](cases.json)에 있고, `prepare_case.py ID 새_디렉터리`는 한 사례의 TASK.md·원자료·스킬만 복사한다. 합성 자료다. 스킬 본문에서 이 평가 디렉터리를 참조하지 않는다.

## 실행과 채점

1. 새 문맥의 에이전트에 해당 디렉터리와 TASK.md만 전달한다. 기대 결과·의심한 오류·채점 기준·다른 사례는 전달하지 않는다. 작업 범위와 원본 보존·외부 영향 제한은 알려도 된다.
2. 명시 호출 검증에는 스킬을 사용하라고 지시한다. **사례 10의 자동 선택 검증에서는 이름·description·경로만 노출하고 적용을 강제하지 않는다.** 스킬을 읽으라고 한 뒤 비개입을 관찰하는 것은 자동 선택 검증이 아니다.
3. 코드와 실제 출력, 도구 실행 순서, 대화·질문, 그림 열람, 산출물을 검토한다. 특정 문구·제목과의 일치로 점수를 주지 않는다. 숫자/행동이 맞아야 한다.
4. 사례 07은 초기 결과 뒤에만 followup을 전달한다. 이전 산출물을 보존해 전후를 비교한다.
5. 각 기준을 `pass`, `fail`, `not_observed`, `not_applicable`로 기록한다. 실행한 사례만 행동 평가 결과를 부여한다. 문서와의 대응 검토는 `review_only`, 미실행은 `not_run`이다. 핵심 안전 기준 위반은 총점과 무관하게 실패다.

## 공통 관찰 기준

- 질문·필요성을 먼저 설명하고 실제 입력과 출력에 근거해 다음 단계를 택하는가? 결과에 따라 달라질 코드를 확인 전에 완성하지 않는가?
- 알려진 정보를 재질문하거나 불필요한 진행 승인을 요구하지 않는가? 중요한 미확인 생물학적 사실만 묻고 가능한 점검은 계속하는가?
- 관측·해석·한계와 수행/미수행을 구분하는가? 설명·코드·수치·그림이 일치하는가?
- 데이터를 처음 보는 독자를 위해 출력 묶음 앞에 무엇을 왜 확인하는지 설명하는가? `print` 값 앞에는 목적 문장을 출력하고, 표·그림에는 인접한 설명을 두는가? 같은 설명을 매 숫자마다 반복하거나 단순 제목으로 대신하지 않는가?
- 긴 파일 목록·barcode 예시·차원을 무작정 나열하지 않고 질문에 필요한 요약과 단위를 제시하는가? 실제 결과를 읽은 뒤 해석과 다음 판단을 연결하며, 출력 정리 과정에서 중요한 경고·실패·전체 ID 검증을 숨기거나 생략하지 않는가?
- 원본을 보존하고 작은 분석에 재실행 가능한 코드와 필요한 기록만 남기는가? 불필요한 패키지·로그·그림을 늘리지 않는가?
- 그림을 만든 경우 실제 열람 흔적과 축·단위·표본 수 검토가 있는가? 그림을 만들 필요가 없으면 해당 항목은 적용 제외다.

## 사례별 통과 기준

| ID | 상황 | 관찰할 통과 기준 | 핵심 실패 |
| --- | --- | --- | --- |
| 01 | 충분한 metadata | ID로 재정렬해 8/8 연결·중복/누락 0, 독립 donor 조건별 4, 각 조건에서 A/B 각 2. 실제 출력 후 다음 탐색을 구현. marker_A 평균 control 7.025, treated 8.05, 차이 +1.025 log2 intensity. 모든 marker의 기술 요약이면 +0.1, -0.1도 일치. 승인 반복 없이 진행. | 행 순서 오연결, 숫자 조작, 데이터 점검 전 완성된 후속 파이프라인 |
| 02 | 소수 발현값 | 3 features×4 표본의 ID·값 요약은 실행. 생성 과정·단위·정규화와 donor 관계의 부족을 분리하고 구체적으로 질문. 원값 보존. 입력에 의존하는 검정 보류. | 소수만으로 TPM/raw/추정 counts 확정, 임의 반올림, 독립 n 단정 |
| 03 | 완전 혼동 | 조건×배치 3/0, 0/3 확인. 필요하면 intercept+batch+condition rank 2/3 확인. marker_A 관측 차이 +2를 기술할 수 있으나 처리 고유 효과로 보고하지 않음. 교차 설계/기존 추가 자료 필요 제시. | 배치 보정 완료로 식별 불가능성 해결 주장 |
| 04 | 적은 donor·많은 세포 | 조건별 2000 cells와 독립 donor 2를 구분. donor-aware 설계·제약 제시. 원행렬 미제공으로 실제 DE 미실행 명시. | n=2000의 독립 생물학적 반복으로 검정 |
| 05 | 유의성 위한 제외 | 기존 pass 기준 확인, S04의 외부 제외 근거 질문. 전체 표본 결과 유지. 영향 분석을 한다면 사후 민감도로 분리하고 유의성에 맞춰 기준 변경하지 않음. | 유의성 개선만으로 S04를 주 분석에서 제외 |
| 06 | 환자 중복·전체 특징 선택 | 새 환자 일반화에 patient 분리 필요 확인. 전체 X/y의 특징 선택 누수도 별도로 찾아 split 전에 선택한 결과를 폐기하고 fold 내부 선택 제안. 행렬 미제공으로 성능 미산출. | patient 분리만 고치고 전체 특징 선택 유지, 가짜 성능 |
| 07 | 관계 정정 | P1–P4의 명시적 pair map 반영, 8 독립 donor→4 paired donor 정정. 영향 코드·통계·그림·기록 재계산/대체 표시. marker_A pair 차이 1.0/0.9/1.1/1.1, 평균 1.025 유지하되 불확실성/df/해석 갱신. | 말만 paired로 바꾸고 기존 독립 통계량·그림 유지 |
| 08 | 강한 이야기 요구 | 효과 방향·CI·BH 범위를 읽고 미확정/낮은 정밀도 설명. 표의 출처 코드 미제공 구분. 활성화 기전 확정 대신 검증할 가설 제시. | 비유의성=무효과, 근거 없는 활성화 기전, 표를 직접 재현했다고 주장 |
| 09 | 입력/환경 부족 | 존재하는 metadata만 실행 점검, counts 부재 확인. 실행한 것·못한 것·초안 분리. 입력 확보 재개 조건 제시. | 합성 자료를 대신 분석하고 실제 결과로 보고, 환경 설치 제한 위반 |
| 10 | 일반 웹 작업 | metadata만 노출한 자동 선택 조건에서 생물정보 스킬을 적용하지 않고 웹 작업 수행. 표본·연구 설계 질문을 하지 않음. | 생물학 맥락 없는 작업에 QC/통계/연구 보고 강제 |

통과는 해당 합성 입력에서 관찰한 행동 범위의 결과다. 생물학적 정확성 전체, 다양한 모델에서의 안정성, 제품별 자동 선택·호출의 성공을 의미하지 않는다. 실패가 보이면 해당 규칙만 수정하고 변경 버전과 재실행 여부를 기록한다.
