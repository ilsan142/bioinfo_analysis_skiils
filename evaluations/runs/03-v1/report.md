# 배치를 고려한 treated − control 비교

**현재 자료에서는 배치를 보정한 처리 효과를 추정할 수 없다.** control 3명은 모두 배치 A, treated 3명은 모두 배치 B여서 처리와 배치가 완전히 겹친다. 관측된 군 차이는 있으나, 그 차이가 처리에서 비롯되었는지 배치에서 비롯되었는지 분리할 정보가 없다. 이는 무효과라는 결론이 아니다.

## 입력과 실제 점검

- 입력: `TASK.md`, `context.md`, `metadata.tsv`, `measurements.tsv`만 사용했다. 외부 자료·문헌이나 다른 프로젝트를 읽지 않았다.
- `context.md`에 따른 의미: 합성 bulk marker 자료, 사람 유래 배양 세포, 동일 배양 조건에서 24시간 처리 비교. 값은 이미 정규화된 log2 intensity다. 가상 marker이므로 실제 유전자 기능을 해석하지 않는다.
- 독립 실험 단위는 donor다. 서로 다른 donor 6명, control 3명과 treated 3명이며 donor당 한 번 측정했다. 짝지어진 자료나 기술 반복이 아니다. 독립성은 제공된 맥락을 따른 것이며 실험 기록으로 별도 검증하지 않았다.
- 실제 확인: 측정 열과 메타데이터 표본 ID 집합 일치, 중복 표본·donor·feature ID 없음, marker 2개 × 표본 6개 = 값 12개, 결측·비유한 값 0개, 전체 범위 4.8–8.7.
- 표본/marker 제외, 결측 대체, 재정규화, 반올림, 배치 보정은 하지 않았다. 분석 전후 모두 표본 6개·marker 2개다. log2 intensity를 count 자료로 취급하지 않았다.

## 설계와 관측 결과

관심 효과는 배치를 같게 두었을 때의 treated − control 평균 차이다. 기준은 control과 배치 A로 두었다.

| 조건 | 배치 A | 배치 B | 독립 donor 수 |
|---|---:|---:|---:|
| control | 3 | 0 | 3 |
| treated | 0 | 3 | 3 |

`intercept + treated + batch_B` 설계행렬의 rank(독립인 열 수)는 **2/3**이다. 처리 열과 배치 B 열이 완전히 동일하다. `X × [0, 1, −1] = 0`이므로 처리 계수에 어떤 값을 더하고 배치 계수에서 같은 값을 빼도 예측값이 같다. 자료가 알려 주는 것은 두 계수의 합뿐이다. 배치 항을 지우거나 역행렬의 대체 계산·자동 배치 보정을 적용해도 처리 고유 효과가 식별되지는 않는다.

그래서 설계 점검 후 후속 분석을 기술통계로 제한했다. 아래 SD는 각 군 donor 3명의 표본 표준편차이며, 처리 효과의 신뢰구간이 아니다.

| 가상 marker | control/A 평균 ± SD | treated/B 평균 ± SD | 관측 treated/B − control/A |
|---|---:|---:|---:|
| marker_A | 5.00 ± 0.20 | 7.00 ± 0.20 | +2.00 |
| marker_B | 8.00 ± 0.20 | 8.50 ± 0.20 | +0.50 |

모든 수치의 단위는 **log2 intensity**다. 차이는 조건과 배치가 함께 다른 두 donor 집단의 관측 차이이며, 배치 보정 처리 효과나 처리에 따른 생물학적 변화로 제시하지 않는다. 군별 범위와 n도 `results/descriptive_summary.tsv`에 포함했다.

처리 효과의 p값·신뢰구간은 계산하지 않았고 다중검정 보정도 적용하지 않았다. 식별 불가능성은 표본 수가 적어 검정력이 낮다는 문제와 다르며, 현 배치 구조 안에서 같은 조합의 donor 수만 늘려도 해결되지 않는다. 두 marker를 donor 반복으로 세지 않았다. 작은 표만으로 질문과 제한을 보여줄 수 있어 그림·PCA는 만들지 않았다.

## 다음 확인과 분석 재개 조건

1. 원 실험 기록에서 조건·배치 라벨이 맞는지 확인하고, 배치가 배양/처리일·시료 준비·측정 중 어느 단계를 뜻하는지 확인한다. 기록 오류라면 근거를 남겨 메타데이터를 수정한 뒤 설계부터 재평가한다. 단지 모형 실행을 위해 라벨을 바꾸지 않는다.
2. 조건 배정의 무작위화와 donor 특성의 균형을 확인한다. 현재 군은 서로 다른 donor이므로 donor 구성 차이도 후보 설명이며, 제공 자료만으로 처리의 인과효과를 입증할 수 없다.
3. 라벨이 맞다면 각 배치 안에 control과 treated가 함께 있도록 독립 생물학적 반복을 확보하는 균형 설계를 우선한다. 가능하면 같은 donor의 세포를 두 처리로 나누고 여러 배치에서 조건을 균형 배정한다. 이때 donor를 짝/블록으로 반영하고 추가 aliquot을 독립 donor로 세지 않는다.
4. 기존 시료의 공통 배치 재측정은 측정 단계의 배치 차이를 평가하는 데 도움이 될 수 있으나, 원래 배양·처리·시료 준비 단계가 조건과 겹친 문제까지 해결하지는 않는다. 먼저 실제 배치 단계를 확인해야 한다.

조건과 배치가 겹쳐 관측되고, 독립 반복 구조와 배정 과정이 확인된 뒤에 배치를 포함한 모형과 처리 contrast를 다시 정의한다. 검정 전에 실험 단위·효과 단위·불확실성과 다중검정 범위를 정한다. 현재 합성 자료의 실행 결과는 실제 생물학적 검증이 아니다.

## 실행 기록과 재실행

1. 스킬과 입력을 읽고 ID/값/설계 점검 부분을 작성해 `python analyze.py`를 실행했다. rank 2/3과 열의 일치를 실제 출력으로 확인했다.
2. 이 결과를 근거로 기술통계만 추가하고 `bash run.sh`로 전체 스크립트를 새 Python 프로세스에서 실행했다. 종료 코드 0이며 생성된 표와 점검 결과를 읽어 확인했다.

```bash
cd /tmp/bio-skill-eval-03
bash run.sh
```

환경: Python 3.12.7, NumPy 2.1.3. 설치 작업 없음. 확률적 연산 없음으로 seed는 필요 없다. 재실행은 `results/`의 세 출력 파일과 `execution.log`를 갱신하며 입력 원본은 보존한다.

- `analyze.py`: ID 연결, 정합성 점검, 설계행렬 rank와 null 방향 검증, 기술통계 계산.
- `run.sh`: 실제 분석 명령을 출력하고 stdout/stderr를 로그에 저장하는 재실행 진입점.
- `execution.log`: 실제 실행 명령·환경·입력 SHA-256·점검 및 요약 결과.
- `results/audit.json`: 입력 체크섬, 정합성, 교차표, 설계의 식별 가능성.
- `results/design_matrix.tsv`: sample ID와 실제 분석 설계행렬.
- `results/descriptive_summary.tsv`: 각 군 n·평균·SD·범위와 관측 군 차이.

별도의 모형 적합·생물학적 검증·외부 문헌 확인은 수행하지 않았다. 실행/형식 점검 통과는 처리 효과가 검증되었다는 의미가 아니다.
