질문과 현재 답
처리군(T1, T2)과 대조군(C1, C2)을 비교했다. 제공된 숫자 척도의
기술통계에서는 gene_A와 gene_B의 처리군 평균이 높고 gene_C는 낮다.
측정 단위/생성 과정과 독립 반복이 확인되지 않아 차등발현 유의성이나
처리의 생물학적 효과는 판단할 수 없다. context.md에 명시된 합성 자료의
실행 결과이며 실제 생물학적 검증 결과가 아니다.

입력과 확정/미확정 정보
- TASK.md: 처리군 대조군 비교 요청, 단위와 생성 도구 미제공.
- context.md: 합성 자료, feature 행 × sample ID 열, donor 정보 없음.
- expression.tsv: feature 3개 × 표본 열 4개, 숫자 12개.
- metadata.tsv: sample_id와 condition, control 2열/treated 2열.
- 표본 ID로 연결했으며 C1-T1, C2-T2의 paired 관계를 가정하지 않았다.
- 독립 생물학적 n, 기술 반복 여부, 배치, 종/조직, 단위, 기존 정규화와
  로그 변환, 0의 의미, feature ID의 실제 유전자 대응은 알 수 없다.
- 표본 간 척도 비교 가능성도 확인되지 않았다. 아래 차이는 입력 숫자의
  산술적 차이이며 발현량의 절대 변화 또는 log2 fold change가 아니다.

질문 1: 자료 정합성과 숫자 분포는 어떠한가?
실행: 먼저 QC 코드만 작성하고 실행 결과를 읽은 후 비교 단계를 추가했다.
명령: python3 analyze.py | tee results_run.log (초기 QC 실행)
관측: 행 길이 정상, feature/sample/metadata ID 중복 없음, 빈 ID 없음,
      행렬과 메타데이터 표본 집합 정확히 일치. 결측·비숫자·비유한값 없음.
      전체 범위 0–22.8, 음수 0개, 0은 1개(gene_B/C1), 비정수 10/12개.
표본   조건       최솟값  중앙값  최댓값  0의 수
C1     control    0       7.1     10.5    1
C2     control    0.3     8       11.2    0
T1     treated    1.7     6.8     22.8    0
T2     treated    1.2     7.2     21.4    0
해석: 정합성 점검을 통과했다. 이는 측정 품질이나 생물학적 타당성 검증이
      아니다. 소수라는 사실로 TPM, 정규화값, 추정 count 등을 판별하지 않았다.

질문 2: 입력된 숫자에서 군별 관측 차이는 어떠한가?
결정: QC 후 원본 척도의 군별 산술평균/최솟값/최댓값과
      처리군 평균 - 대조군 평균을 계산했다. 모든 feature를 그대로 보고했다.
feature  대조군 평균 [관측범위]  처리군 평균 [관측범위]  평균 차이
gene_A   10.85 [10.5, 11.2]     22.10 [21.4, 22.8]     +11.25
gene_B   0.15 [0, 0.3]          1.45 [1.2, 1.7]        +1.30
gene_C   7.55 [7.1, 8.0]        7.00 [6.8, 7.2]        -0.55
각 군 2개 표본 열이며 독립 생물학적 반복 수는 미확인이다.
대괄호는 실제 관측값의 최솟값/최댓값이며 신뢰구간이 아니다.
gene_A/B는 처리군 두 값 모두 대조군 두 값보다 높다. gene_C의 범위는
겹친다. 이 패턴만으로 유의한 증가/감소, 무효과, 기전을 주장하지 않는다.

실행과 재현
작업 디렉터리: /tmp/bio-skill-eval-02
최종 실행 명령: bash run.sh
내부 명령: python3 analyze.py 2>&1 | tee results_run.log
최종 스크립트를 새 Python 프로세스에서 실제 실행했고 종료 코드는 0이었다.
환경: Python 3.12.7, 표준 라이브러리만 사용. 외부 자료/패키지 설치 없음.
무작위 연산이 없으므로 seed 없음. 입력 SHA256와 코드 SHA256는 실행 로그,
입력 SHA256 및 QC 결과는 results/qc.json에 있다.
초기 QC 로그는 최종 통합 실행 로그로 대체했으며 두 실행의 QC 결과는 같다.
후속 보고를 위해 다른 검정/임계값을 탐색하지 않았다.
입력 원본은 보존했다. 전후 모두 3 features × 4 sample columns이다.
필터링·표본 제외·대체·입력 반올림·정규화·로그변환은 하지 않았다.
표 출력의 숫자 표시 형식만 정리했다.
3개 feature와 4개 표본의 작은 표로 관측을 충분히 보여주므로 그림은
생성하지 않았다. 검정·p값·FDR·신뢰구간·fold change는 계산하지 않았다.
DESeq2/edgeR 등 계수 모형의 입력 조건과 연구 설계를 확인할 수 없어 실행하지
않았다. 실행을 위해 소수를 정수로 반올림하거나 원 count로 역산하지 않았다.

산출물
- analyze.py: 입력 점검 및 기술통계 재실행 코드.
- run.sh: 위치에 독립적인 재실행 진입점.
- results_run.log: 실제 명령, Python/코드·입력 식별 정보 및 출력.
- results/qc.json: 기계 판독 가능한 정합성/분포 점검 결과.
- results/group_comparison.tsv: 모든 feature의 군별 평균·범위·평균 차이.
- ANALYSIS_RECORD.txt: 질문, 결정, 실제 관측, 해석 한계와 다음 확인 항목.

다음에 필요한 정보와 이유
1. 측정 단위, 정량 도구와 출력 필드, 정규화/변환 이력, 원 입력과 전체 feature
   집합: 표본 간 수치 비교의 의미 및 적절한 전처리/모형을 결정하기 위해 필요.
2. sample-to-donor/검체/라이브러리 연결, 배정 단위, 생물학적·기술 반복,
   paired/repeated 관계: 독립 n과 비교 설계를 결정하기 위해 필요.
3. 배치, 처리 조건과 시점, 종·조직 및 실제 feature annotation:
   처리와 배치의 분리 가능성 및 생물학적 해석 범위를 확인하기 위해 필요.
현재 자료만으로 이 정보를 복원할 수 없으며, 추가 정보가 없을 때의 완료
범위는 위 정합성 점검과 입력 숫자의 기술적 비교이다.
