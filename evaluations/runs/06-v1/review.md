# 새 환자 질병 예측 평가 검토

현재 평가로는 **처음 보는 환자에 대한 예측 성능을 타당하게 주장할 수 없다.** 제공 분할표에서 환자가 훈련·평가에 중복되고, 코드에서는 평가 대상의 라벨까지 이용해 특징을 선택한다. 두 문제를 모두 수정한 뒤 원래 특징부터 재평가해야 한다. 점수가 얼마나 부풀려졌는지는 현재 자료로 계산할 수 없다.

## 실제 확인 결과

입력은 `TASK.md`, `context.md`, `pipeline.py`, `split.tsv`이다. `context.md`에 따라 실제 특징 행렬 X와 질병 라벨 y는 제공되지 않았다. 코드 주석은 행이 동일 환자의 두 방문 자료임을 설명한다. 일반화 대상은 요청에 명시된 **새 환자**이므로, 분할과 독립성의 기준은 환자다.

| 환자 | 훈련 행 | 평가 행 | 새 환자로 평가되는가 |
|---|---|---|---|
| P1 | R1 | R2 | 아니오 |
| P2 | R3 | R4 | 아니오 |

실행한 분할표 점검 결과: 4행, 고유 환자 2명, 훈련 2행/2명, 평가 2행/2명, 중복 환자 2명(P1, P2), 훈련에 없는 평가 환자 0명이다. 평가 행 2개 모두 훈련에서 본 환자의 자료다. 행 ID 중복은 없다. 4개 방문을 독립 환자 4명으로 세면 안 된다.

1. **환자 단위 중복:** 동일 환자의 방문에는 공유되는 생물학적·측정 특성이 있을 수 있다. 이 분할은 새 환자로의 일반화 검증이 아니다. `pipeline.py:7`의 `patient_id` 인자는 함수 본문에서 사용되지 않으며, 9행은 환자 그룹을 반영하지 않고 행을 나눈다. 무작위 seed 고정은 이러한 문제를 해결하지 않는다.
2. **평가 라벨의 특징 선택 유입:** `pipeline.py:8`은 `SelectKBest(f_classif, k=10).fit_transform(X, y)`를 전체 X와 y에 적용한다. 이어 9행에서 분할하므로 평가 라벨이 선택된 특징에 영향을 준다. 이후 로지스틱 회귀를 훈련 행에만 적합해도 이미 생긴 정보 누출은 남는다. 성능은 낙관적으로 치우칠 수 있으나 상승 폭이나 방향을 실제로 측정한 것은 아니다.
3. **분할표와 실행 코드의 연결 미확인:** 코드는 `split.tsv`를 읽지 않고 자체 무작위 분할을 만든다. 따라서 표에서 관측한 100% 환자 중복을 어떤 실제 모델 실행의 분할률이라고 단정할 수 없다. 분할표 자체의 중복과 코드 자체의 누출은 각각 확인된 문제다. 원래 실행의 행 ID 목록은 제공되지 않았다.
4. **성능 근거 부재:** 11행은 `model.score(test_x, test_y)`로 행 단위 정확도를 반환하지만, 제공된 성능값은 없다. X/y가 없어 함수 실행, 질병군별 환자 수, 라벨의 방문 간 일관성, 실제 예측값, 성능과 불확실성을 계산하지 않았다.

## 재평가에 필요한 변경과 조건

아래는 제안이며 실행된 재평가가 아니다.

1. 원래 특징 행렬, 라벨, 환자 ID, 방문/측정 시점과 행 ID 연결을 확보한다. 첫 방문의 현재 질병 판별인지 미래 발병 예측인지 확정하고, 예측 시점에 사용할 수 있는 특징과 라벨 정의를 명시한다. 현재 자료만으로 이 임상적 정의를 만들 수 없다.
2. 특징 선택 **이전**에 환자 단위로 훈련·평가를 나누고 동일 환자의 모든 방문을 한쪽에 둔다. 분할 결과를 행 ID와 환자 ID로 저장하고 두 환자 집합의 교집합이 빈지 확인한다. `GroupShuffleSplit` 또는 환자 그룹을 반영한 교차검증을 사용할 수 있다. 이미 전체 자료로 선택한 10개 특징만 재분할하면 누수가 남는다.
3. 각 훈련 부분에서만 특징 선택을 적합하도록 `Pipeline([SelectKBest(...), LogisticRegression(...)])` 형태로 구성한다. 추가되는 결측치 보정·표준화도 같은 원칙을 따른다. 평가 자료에는 훈련에서 학습한 변환만 적용한다. k나 모델 설정을 선택한다면 훈련 자료 내부에서 환자 단위 검증을 하고, 최종 평가 자료는 선택 과정에 사용하지 않는다.
4. 분할 전에 질병군별 **환자 수**와 각 fold의 클래스 구성을 확인한다. 제공 표의 환자는 총 2명뿐이므로 이를 재분할해도 신뢰할 만한 새 환자 성능을 평가할 근거가 부족하다. 환자별 라벨이 고정이고 환자마다 클래스가 다르다면 한 명을 훈련에 남기는 분할은 훈련 클래스가 하나뿐일 수 있다. 라벨이 없으므로 실제로 그런지는 알 수 없다. 추가 독립 환자와 충분한 클래스별 표본이 필요하며, 임의의 최소 수치를 제시하지 않는다.
5. 평가 단위를 먼저 정한다. 새 환자의 첫 방문을 평가한다면 환자당 해당 방문 한 개를 사용하고, 여러 방문의 현재 상태를 평가한다면 반복 방문 구조를 명시한다. 여러 방문을 독립 표본으로 취급해 신뢰구간을 만들지 않는다. 충분한 환자 수가 확보된 뒤 환자 단위를 반영한 불확실성을 산출한다. 질병군 분포와 목적에 맞춰 정확도 외에 민감도·특이도, 구분 성능, 확률 보정을 검토하고 선택 기준과 임계값을 평가 자료에서 조정하지 않는다.

## 실행 및 재현 기록

원본 입력은 변경하지 않았다. 제공 스킬의 예측모델 절과 분석 기록 지침을 적용했다. 외부 프로젝트·자료를 읽거나 패키지를 설치하지 않았다.

실행 환경: Python 3.12.7, 표준 라이브러리만 사용. 실행 명령과 종료 결과:

```bash
cd /tmp/bio-skill-eval-06
python3 audit.py > audit_run.log
```

실제 실행 종료코드 0. `audit.py`는 분할표를 집계하고 Python AST로 원본 코드의 특징 선택·분할 순서와 `patient_id` 사용 여부를 점검했다. 입력 파일 SHA-256, 실행 시각, 명령, Python 버전은 `audit_results.json`에 기록되어 있다. 동일 결과의 표준 출력은 `audit_run.log`에 보관했다. 재실행 시 감사 결과와 로그를 갱신하며 시각은 달라진다. 이 스크립트는 제공된 짧은 코드 구조를 위한 감사이며 임의 코드의 모든 누출을 탐지하는 범용 도구가 아니다.

- `audit.py`: 재실행 코드.
- `audit_results.json`: 기계가 읽을 수 있는 실제 감사 결과와 입력 해시.
- `audit_run.log`: 실행 표준 출력.
- `review.md`: 판단, 근거, 한계와 재평가 조건을 묶은 본 기록.

완료된 작업은 **분할표 분석과 정적 코드 검토**다. 모델 학습·성능 재계산·수정 모델 검증·독립 생물학적 또는 임상적 검증은 수행되지 않았다. 작은 표로 판단 근거가 충분하여 그림과 통계 검정은 만들지 않았다.
