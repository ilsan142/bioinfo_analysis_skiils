# 가벼운 분석 기록과 완료 점검

새 기록 형식을 정하거나 최종 결과를 묶을 때 읽는다. 기존 노트북·분석 문서에 필요한 내용이 있으면 그대로 활용한다. 아래는 선택 가능한 틀이며, 별도 파일이나 모든 필드를 강제하지 않는다.

## 질문 단위 기록

```text
질문 / 필요한 이유:
확인한 입력과 의미: 경로·출처·표본/feature 단위·기존 처리
확인한 설계 / 잠정 가정 / 미확인 사항:
결정: 비교·기준 집단·공변량·필터·집계·제외 근거
시점: 결과 전에 정함 / 결과 후 탐색 / 오류·실험 정보 정정
실행: 코드 위치·명령 또는 노트북 실행 순서
관측: 실제 n·효과/단위·불확실성·경고·처리 전후 변화
해석과 한계:
다음 질문과 이유 / 연구자에게 필요한 정보:
```

## 재실행에 필요한 최소 연결

- 입력 자료의 출처와 현재 버전/경로, 원본과 변환본의 구분. 동일 파일을 식별할 필요가 있으면 checksum을 사용한다.
- 분석 코드·핵심 파라미터와 결과 표/그림을 직접 연결한다. 데이터 접근 권한이나 외부 입력이 필요하면 재실행 조건으로 기록한다.
- 사용한 언어·패키지·참조 데이터 버전 등 결과에 영향을 주는 환경, 확률적 연산의 seed와 비결정적 한계. 작은 분석에 모든 시스템 패키지 목록을 강제하지 않는다.
- 스크립트 명령이나 노트북의 처음부터 실행 순서. 실제 깨끗한 재실행 여부와 실패를 기록한다. 성공한 셀만 골라 실행한 상태를 완전 재현으로 부르지 않는다.
- 그림은 열어 확인한 항목과 남은 문제를 적는다. 열지 못했다면 미검토로 표시한다.

## 정정과 대체

정정된 정보의 출처, 기존 가정과 새 관계, 영향받는 코드·표·그림·설명을 식별한다. 원본은 보존하고 수정 메타데이터와 현재 산출물을 구별한다. 필요한 계산을 다시 실행하고 이전 결과에는 “대체됨”을 표시한다. 정정 후 효과가 같더라도 n·불확실성·검정·그림·해석이 여전히 맞는지 확인한다.

## 최종 보고에 남길 내용

1. 질문과 현재의 답. 자료로 답할 수 없는 부분도 답의 일부로 명시한다.
2. 사용 자료·표본과 주요 실제 관측. 효과·단위·불확실성·독립 n은 가능한 범위에서 함께 제시한다.
3. 선택한 방법과 핵심 결정의 이유, 주요 전처리 전후 변화와 사후 탐색 여부.
4. 결론의 범위와 미해결 사항. 문헌 사실, 현재 실행 결과, 후보 설명·후속 제안을 구분한다.
5. 코드·표·그림·기록 위치와 다시 실행하는 방법, 실제 실행·재실행·시각 검토 상태.
6. 다음 확인 항목과 그 확인이 줄일 불확실성.

보고를 닫기 전에 “질문·자료·선택 이유·관측·한계·다음 확인”을 연구자가 설명할 수 있는지 점검한다. 성공 문구 대신 산출물과 근거를 남긴다. 소프트웨어/형식 검증, 합성 예시 실행, 시나리오 검토, 실제 자료 분석, 독립 생물학적 검증은 서로 다른 증거 수준이다.
